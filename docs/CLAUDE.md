# CLAUDE.md — Docs

## Style

The recovery docs are read under pressure, after something has already gone wrong.
Write them to be followed, not studied.

- **Bite-sized:** one action per step, a few short lines per procedure.
  Split anything that needs scrolling to understand.
- **Plain words:** say what to do, not how the system works.
  Prefer "start the backup" over a tool's own terms; explain a necessary term once, where it first appears.
- **Doing before reasoning:** put the step first and the reason, if one is needed, after it in a short clause.
- **Concrete:** name the exact command, file or host, and what a success looks like.
- **No cross-reading:** a procedure shouldn't need another page to be followed.
  Link only to a different procedure that comes next.
